# 徒步会话完整流程 v0.1

更新日期：2026-06-05

## 流程目标

一次徒步会话要完成从 iPhone 准备路线、同步到 Apple Watch、Watch 独立导航和记录、结束后回传复盘的闭环。

这个流程的核心原则：

1. 出发前的复杂操作放在 iPhone。
2. 行进中的主操作放在 Watch。
3. Watch 与 iPhone 断连时，Watch 仍能继续记录和导航。
4. 结束后必须能把实际轨迹安全同步回 iPhone。
5. 路线同步是导航主路径；路线未下发时，Watch 仍可进入自由记录模式完成轨迹记录闭环，但不提供路线跟随、偏航或转向提醒。
6. 任意路线被用于导航前，都必须经过 Watch 端确认层；路线下载、同步或安装成功，只代表路线可用，不代表已经绑定当前会话。

## 主路径概览

```txt
iPhone 获取远端路线或导入 GPX
  -> iPhone 路线详情确认
  -> 同步路线到 Watch
  -> Watch 路线就绪
  -> Watch 开始徒步
  -> Watch 地图导航 + 轨迹记录
  -> Watch 暂停/继续/提醒
  -> Watch 结束徒步
  -> 轨迹回传 iPhone
  -> iPhone 复盘详情
```

无路线自由记录兜底：

```txt
Watch 无可用计划路线
  -> Watch 地图页进入自由记录
  -> Watch 开始记录
  -> Watch 地图显示当前位置 + 已走轨迹
  -> Watch 暂停/继续
  -> Watch 二次确认结束
  -> 轨迹回传 iPhone
  -> iPhone 按无计划路线复盘
```

自由记录中途接入路线：

```txt
Watch 正在自由记录
  -> iPhone 后续下发 GPX / 路线
  -> Watch 安装路线但不立即改写会话
  -> 数据判断层计算当前位置到路线的最近投影点和距离
  -> 如果距离过远，提示路线离当前位置较远，仅安装为下次可用
  -> 如果距离可接受，进入用户确认层
  -> 用户确认后从当前定位点附近的最近路线投影点开始路线跟随
  -> 历史轨迹不补算路线进度、偏航或转向事件
```

## 阶段 1：iPhone 准备路线

### 用户目标

用户把一条计划徒步路线放进 App，并确认路线基本可信。

### 入口

1. 从远端路线列表选择路线。
2. 按路线名称、编号或区域搜索远端路线。
3. 从文件 App 分享 GPX 到 App。
4. 在 App 内点击导入 GPX。
5. 从历史路线或本地路线库选择。

### iPhone 显示

1. 路线名称。
2. 地图上的计划路线。
3. 起点和终点。
4. 距离。
5. 预计爬升。
6. 路线点数量。
7. 可识别的关键点和转向点数量。

### 系统处理

1. 远端路线列表只拉取摘要，完整点序列在进入详情时按需下载。
2. 下载远端路线详情后校验版本和 checksum，并安装成本地 `HikingRoute`。
3. GPX 导入时解析点序列。
4. 生成路线摘要。
5. 计算路线距离。
6. 尝试识别转向点。
7. 检查路线是否点数过多，必要时生成 Watch 端简化路线。
8. 保存原始路线和简化路线。

### 异常

| 异常 | 处理 |
| --- | --- |
| 远端列表刷新失败 | 显示失败原因，保留本地已保存路线 |
| 远端路线详情下载失败 | 保留列表摘要，允许重试 |
| 远端路线 checksum 不匹配 | 不安装路线，提示重新下载 |
| GPX 无有效轨迹点 | 显示导入失败 |
| 点数过少 | 提示路线可能无法导航 |
| 点数过多 | 自动生成简化路线，保留原始数据 |
| 路线无海拔 | 允许继续，爬升数据标记为未知 |

## 阶段 2：iPhone 路线详情确认

### 用户目标

用户在出发前确认这条路线就是要走的路线。

### iPhone 显示

1. 地图全览。
2. 路线距离。
3. 预计耗时。
4. 累计爬升。
5. 起点、终点。
6. 关键点列表。
7. 转向点概览。
8. “同步到 Watch”按钮。

### 重要决策

路线详情页要让用户知道：

1. 当前路线是否已经同步到 Watch。
2. Watch 是否在线。
3. Watch 电量是否适合开始徒步。
4. 是否存在缺失权限。

## 阶段 3：同步路线到 Watch

### 用户目标

用户把本次路线可靠下发到 Watch。

### 同步内容

| 数据 | 用途 |
| --- | --- |
| 路线基本信息 | Watch 路线卡片和会话标题 |
| 简化路线点 | Watch 地图绘制和偏航判断 |
| 原始路线摘要 | 复盘和一致性校验 |
| 起点/终点 | 地图标记 |
| 转向点 | 接近转向提醒 |
| 关键点 | 补给、风险、拍照点等提醒 |
| 默认提醒配置 | 偏航阈值、转向提醒距离等 |

### 同步状态

| 状态 | iPhone 表现 | Watch 表现 |
| --- | --- | --- |
| 未同步 | 显示“同步到 Watch” | 不显示路线 |
| 同步中 | 显示进度 | 显示接收中 |
| 已同步 | 显示“Watch 已就绪” | 显示路线卡片，等待用户确认使用 |
| 同步失败 | 显示失败原因和重试 | 保留上一次可用路线 |
| Watch 不在线 | 提示稍后自动同步 | 保持本地状态 |

### 产品原则

1. 同步失败不能覆盖 Watch 上已有的可用路线。
2. Watch 端必须能明确显示当前路线名称和同步时间。
3. 如果 Watch 不在线，iPhone 可以排队同步，但要告诉用户还没就绪。
4. 路线安装成功后只进入“可用路线”状态，不能自动成为当前导航路线。

## 阶段 4：Watch 路线就绪

### 用户目标

用户在 Watch 上确认路线已经可用，并准备开始。

### Watch 显示

1. 路线名称。
2. 路线距离。
3. 起点方向或当前位置到起点距离。
4. Watch 电量。
5. 定位状态。
6. “使用此路线开始”按钮。

### 使用路线确认层

路线就绪页是 Watch 端的正式确认层。

1. 用户必须在 Watch 上确认使用某条路线，才能创建绑定该路线的 `HikingSession`。
2. 如果 Watch 上有多条已安装路线，开始前必须明确选择其中一条，不能默认使用最近同步路线。
3. 如果当前位置离路线起点较远，确认层显示距离提示，但不强制阻断。
4. 用户未确认时，路线保持已安装状态，不生成路线进度、偏航或转向事件。
5. iPhone 只能下发和展示同步状态，不能远程替用户确认某条路线作为当前导航基准。

### 可选提示

1. 当前位置离路线起点较远。
2. 定位权限缺失。
3. HealthKit 权限缺失。
4. 电量较低。

### 开始前检查

| 检查项 | 阻断开始 | 说明 |
| --- | --- | --- |
| 无路线数据 | 否 | 不能进入路线跟随，但可进入自由记录 |
| 无定位权限 | 是 | 无法导航和记录 |
| 无 HealthKit 权限 | 否 | 可继续地图导航，但运动数据不完整 |
| Watch 电量低 | 否 | 提醒用户，允许继续 |
| iPhone 断连 | 否 | Watch 可独立开始 |

### 无路线自由记录

如果 Watch 没有可用计划路线：

1. Watch 地图页不显示等待路线作为阻断状态。
2. 地图页显示“自由记录”和“无路线也可开始”。
3. 用户可直接开始会话。
4. 会话仍启动定位、运动记录、本地存储和结束回传。
5. `nearestRouteDistanceMeters` 和 `routeProgressMeters` 为空。
6. 不生成偏航事件和转向提醒事件。
7. 结束摘要仍包含距离、用时、轨迹点数、心率和能量等可用数据。

### 自由记录中途收到路线

如果 Watch 已经开始自由记录，iPhone 后续下发 GPX 或路线，MVP 允许进入“中途接入路线”判断，但不能静默切换。

数据判断层：

1. Watch 先按普通路线下发流程接收、校验和安装路线。
2. 安装后读取当前可信定位点，不使用低可信定位点触发接入判断。
3. 计算当前定位点到下发路线的最近投影点、最近路段 index、`routeProgressMeters` 和距离。
4. 如果当前位置距离路线超过中途接入阈值，路线只标记为已安装，不绑定当前会话。
5. 如果当前位置距离路线在阈值内，进入用户确认层。

确认层：

1. Watch 明确提示“收到路线，是否从当前位置开始按路线导航”。
2. 用户确认前，当前会话继续保持自由记录，不计算路线进度、偏航或转向提醒。
3. 用户确认后，会话从确认时刻绑定该路线版本。
4. 绑定后的第一个路线进度锚点，是当前定位点在路线上的最近投影点。
5. 绑定前已经产生的 `TrackPoint` 保留为实际轨迹，但不补算 `nearestRouteDistanceMeters`、`routeProgressMeters`、偏航事件或转向事件。
6. 用户拒绝或超时不确认时，路线保留为下次可用，当前会话继续自由记录。

默认阈值建议：

| 阈值 | 默认值 | 说明 |
| --- | --- | --- |
| `midSessionRouteAttachMaxDistanceMeters` | 100m | 超过后认为下发路线与当前位置相隔较远，不建议中途接入 |
| `midSessionRouteAttachStrongDistanceMeters` | 30m | 小于该距离可显示更积极的接入提示 |

该阈值需要真机和实地徒步验证，不能视为最终实测值。

## 阶段 5：Watch 开始徒步

### 用户目标

用户在 Watch 上开始本次徒步记录。

### 系统处理

1. 创建徒步会话。
2. 启动定位更新。
3. 启动运动记录。
4. 记录开始时间。
5. 初始化实际轨迹。
6. 进入地图页。
7. 将会话状态写入本地存储。

### Watch 首屏

开始后直接进入地图页，不进入数据页。

地图页初始显示：

1. 当前定位点。
2. 计划路线。
3. 已走轨迹。
4. 起点和终点。
5. 顶部状态胶囊。
6. 底部下一步提示。

自由记录时，地图页初始显示当前定位点、已走轨迹、顶部“自由记录中”和底部“记录实际轨迹”，不显示计划路线、起点、终点、剩余距离和偏航状态。

## 阶段 6：行进中

### 用户目标

用户通过 Watch 完成路线跟随和状态判断。

### Watch 持续处理

1. 采集定位点。
2. 追加实际轨迹。
3. 将当前位置投影到计划路线。
4. 计算偏航距离。
5. 计算剩余距离。
6. 判断是否接近转向点。
7. 判断是否接近终点。
8. 采集运动数据。
9. 本地保存增量轨迹。
10. 在可用时向 iPhone 同步轻量状态。

自由记录时跳过第 3-7 项路线相关处理，只保留定位采样、轨迹追加、运动数据、本地保存和轻量状态同步。

### Watch 用户可见状态

1. 正常行进。
2. 接近转向点。
3. 偏航。
4. 回到路线。
5. 定位不稳。
6. 暂停中。
7. 接近终点。
8. 低电量。

### iPhone 行进中状态

iPhone 不作为主导航，但可以显示：

1. 当前会话进行中。
2. Watch 电量和连接状态。
3. 当前距离和用时。
4. 最近同步时间。

如果 iPhone 不在身边，不影响 Watch 会话。

## 阶段 7：提醒和干预

### 接近转向点

触发：

1. 用户仍在路线附近。
2. 前方转向点距离小于提醒阈值。
3. 当前转向点尚未提醒。

Watch 行为：

1. 轻震一次。
2. 高亮下一段路线。
3. 显示“前方 Xm 左转/右转/急转”。

### 偏航

触发：

1. 定位精度满足判断要求。
2. 连续多个定位点超过偏航阈值。

Watch 行为：

1. 明显震动。
2. 显示偏航距离。
3. 显示当前位置到最近路线点的连接线。
4. 提示回到路线的大致方向。

用户选择：

1. 回到路线。
2. 暂时忽略偏航。
3. 结束徒步。
4. 后续能力：进入返航。

### 定位不稳

触发：

1. 定位精度差。
2. 定位更新中断。

Watch 行为：

1. 显示“定位不稳”。
2. 降低偏航提醒优先级。
3. 继续记录可用轨迹点。

### 低电量

触发：

1. Watch 电量低于阈值。

Watch 行为：

1. 显示电量提醒。
2. 提供省电建议。
3. 可降低地图刷新和轨迹采样频率。
4. 保留路线跟随和轨迹记录。

## 阶段 8：暂停和继续

### 暂停入口

1. 长按地图打开菜单。
2. 最小控制入口点击暂停；完整控制页后置。
3. 系统检测到长时间静止时可建议暂停，但不自动暂停。

### 暂停后

1. 停止写入正式轨迹点。
2. 继续低频更新当前位置。
3. 运动记录进入暂停状态。
4. Watch 顶部显示“已暂停”。

### 继续后

1. 恢复定位采样。
2. 恢复轨迹写入。
3. 恢复运动记录。
4. 地图回到正常行进状态。

## 阶段 9：结束徒步

### 结束入口

1. 长按地图打开菜单。
2. 最小控制入口点击结束；完整控制页后置。
3. 接近终点后 Watch 提示是否结束。

### 结束确认

Watch 必须二次确认，避免误触。

确认页显示：

1. 本次距离。
2. 本次用时。
3. 是否保存轨迹。
4. 结束按钮。

### 系统处理

1. 停止定位更新。
2. 停止运动记录。
3. 关闭当前会话。
4. 保存完整轨迹。
5. 生成会话摘要。
6. 尝试同步到 iPhone。
7. 如果无法同步，保留本地待同步记录。

## 阶段 10：同步回 iPhone

### 同步内容

| 数据 | 用途 |
| --- | --- |
| 会话摘要 | 历史列表展示 |
| 实际轨迹点 | 地图复盘 |
| 偏航事件 | 复盘风险点 |
| 转向提醒事件 | 分析提醒是否有效 |
| 暂停区间 | 准确计算移动时间 |
| HealthKit 运动引用 | 心率、能量、运动数据关联 |

### 同步原则

1. Watch 本地先保存，再同步。
2. 同步失败可重试。
3. iPhone 不应因为重复同步产生重复记录。
4. iPhone 收到完整会话后回执给 Watch。
5. Watch 收到回执后可标记为已同步，但不立即删除本地数据。

## 阶段 11：iPhone 复盘

### 用户目标

用户回看本次徒步结果，并确认轨迹保存成功。

### iPhone 显示

1. 地图叠加计划路线和实际轨迹。
2. 距离。
3. 用时。
4. 移动时间。
5. 累计爬升。
6. 平均速度。
7. 心率摘要。
8. 偏航事件列表。
9. 暂停区间。
10. GPX 导出入口。

### 复盘重点

第一版复盘不做复杂训练分析，重点展示：

1. 实际走了哪里。
2. 是否偏离过计划路线。
3. 偏离发生在哪里。
4. 最终轨迹是否安全保存。

## 关键异常流程

### Watch 与 iPhone 断连

行为：

1. Watch 继续独立导航和记录。
2. iPhone 显示最近同步时间。
3. 重新连接后自动补传。

### Watch App 被系统挂起或重启

行为：

1. 从本地会话状态恢复。
2. 继续追加轨迹。
3. 标记恢复事件。

### 地图底图加载失败

行为：

1. 继续显示计划路线线框。
2. 继续显示当前位置和已走轨迹。
3. 不影响偏航判断和轨迹记录。

### HealthKit 运动记录失败

行为：

1. 地图导航和轨迹记录继续。
2. 标记运动数据不完整。
3. 结束后复盘缺少心率或能量数据。

### 电量极低

行为：

1. 提醒用户。
2. 降低地图刷新频率。
3. 降低轨迹采样频率。
4. 优先保留定位、偏航判断和本地保存。

## MVP 验收标准

1. 用户能从 iPhone 获取远端路线或导入 GPX，并看到路线详情。
2. 用户能把路线同步到 Watch。
3. Watch 能在 iPhone 断连时开始并完成徒步。
4. Watch 地图页能显示计划路线、当前位置和已走轨迹。
5. 行进中能产生偏航提醒和转向点提醒。
6. 暂停、继续、结束流程不会丢失轨迹。
7. 结束后实际轨迹能回传到 iPhone。
8. iPhone 复盘页能叠加计划路线和实际轨迹。
9. 同步失败时 Watch 本地仍保留待同步记录。
10. 地图底图失败时核心记录能力仍可用。
