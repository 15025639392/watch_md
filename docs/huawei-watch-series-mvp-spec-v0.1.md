# 华为 WATCH 系列徒步 App MVP 规格 v0.1

更新日期：2026-06-06  
适用范围：Apple Watch MVP 之后的华为 WATCH 数字系列验证线，优先面向 `HUAWEI WATCH 5` / `HUAWEI WATCH 4`。本文不改变当前首发 Apple Watch / watchOS 的 MVP 范围。

## 产品定位

华为 WATCH 系列 MVP 的目标是验证“完整智能手表 App”能否承载徒步导航闭环。

一句话定义：

> 华为手机负责路线准备、路线下发和复盘，WATCH 数字系列负责腕上路线跟随、偏航提醒、轨迹记录、暂停/继续/结束和结束后回传。

它不是 GT 系列轻量提醒版，也不是直接照搬 Apple Watch 实现。WATCH 数字系列规格参考 WatchOS MVP 的产品结构，但所有后台定位、地图底图、手表端安装、Wear Engine 通信、Health Kit 数据和 AppGallery 分发能力都必须经华为真机验证后才能变成正式承诺。

## 核心用户场景

### 出发前

用户在华为手机或 Android 手机上选择远端路线或导入 GPX，查看路线距离、爬升、预计耗时和关键点，并通过 Wear Engine 或后续确认的协同链路同步到 WATCH。

### 行进中

用户主要看 WATCH。已同步计划路线时，WATCH 首屏显示地图或路线视图、计划路线、已走轨迹、当前位置、方向和偏航状态。

如果出发时路线尚未下发，WATCH 可以进入自由记录模式，记录实际轨迹、时间、距离和基础运动数据，但不显示计划路线、不计算剩余距离、不触发偏航或转向提醒。

### 风险发生时

当用户偏离路线、接近关键点、定位不稳或电量不足时，WATCH 通过震动、状态条或通知提醒用户。日落风险、天气风险、长时间停留和复杂返航判断不进入 WATCH 系列首轮 MVP。

### 结束后

用户在 WATCH 上结束徒步，实际轨迹和会话摘要回传手机。手机展示计划路线与实际轨迹叠加、偏航事件、距离、时长、爬升、速度和可获得的健康数据。

## 端分工

| 端 | 产品职责 | 不承担 |
| --- | --- | --- |
| 华为 / Android 手机 | 远端路线列表、GPX 导入、路线详情、路线同步、历史记录、运动复盘、设置、账号和权限管理 | 徒步中的主导航视图 |
| WATCH 数字系列 | 腕上地图或路线视图、路线跟随、实时轨迹记录、偏航提醒、关键点提醒、暂停/继续/结束、会话摘要回传 | 复杂路线编辑、路线社区、深度复盘分析、完整离线地图承诺 |
| 服务端 | 路线目录、路线详情、版本校验、后续账号同步 | 直接控制手表运动会话 |

## MVP 功能范围

第一版 WATCH 系列只验证一个完整闭环：

1. 手机从远端接口获取路线列表，并支持导入 GPX。
2. 手机生成 WATCH 可用的路线 payload，包含简化路线点、起终点、关键点、路线摘要和校验信息。
3. 手机通过 Wear Engine 或已验证通信链路向 WATCH 下发路线。
4. WATCH 收到路线后保存本地，并回传 ACK。
5. WATCH 要求用户确认“使用此路线开始”，不能静默切换当前导航路线。
6. WATCH 首屏进入地图或路线跟随视图。
7. 徒步开始后 WATCH 记录实际轨迹。
8. WATCH 叠加或展示已走轨迹，并显示当前位置与方向。
9. 用户偏离路线时 WATCH 震动提醒。
10. 用户可暂停、继续、结束徒步。
11. 结束后 WATCH 回传实际轨迹、会话摘要和事件列表。
12. 手机展示计划路线与实际轨迹复盘。
13. 无计划路线时 WATCH 允许自由记录；该模式不提供路线跟随、偏航或转向提醒。
14. 自由记录中途收到路线时，WATCH 先做距离判断和用户确认；确认后从最近路线投影点开始后续导航。

## Watch 端页面结构

WATCH 数字系列可以按完整手表 App 设计，但首轮仍以地图页为核心。

| 页面 | 目标 | MVP 内容 |
| --- | --- | --- |
| 地图页 / 路线页 | 抬腕判断方向和是否偏航 | 底图或简化路线画布、计划路线、已走轨迹、当前位置、方向、偏航距离、关键点 |
| 数据页 | 查看当前运动状态 | 距离、时长、海拔、爬升、速度、心率可用状态 |
| 安全页 | 查看风险状态 | 偏航、定位、电量、连接状态 |
| 控制页 | 执行低频操作 | 开始、暂停、继续、结束、二次确认 |

### 地图页能力分级

| 能力 | WATCH 系列 MVP 判断 |
| --- | --- |
| 标准底图 | 需要真机验证可用地图组件、授权、性能和离线表现 |
| 自绘路线 | P0 必须验证，作为底图不可用时的兜底 |
| 计划路线 | P0 必须支持 |
| 已走轨迹 | P0 必须支持 |
| 当前定位点和方向 | P0 必须支持 |
| 偏航连接线 | P1，可先用距离和方向文本替代 |
| 离线地图 | 不作为 MVP 承诺，只作为后续专项 |
| 多地图源切换 | 不进入 MVP |

## 技术假设

| 能力 | 首选验证路径 | 状态 |
| --- | --- | --- |
| 手表端应用 | DevEco Studio `Wearable`、ArkTS、ArkUI | 需要 WATCH 5 / 4 真机验证 |
| 手机-手表同步 | Wear Engine 消息 / 文件能力 | 需要验证传输大小、后台稳定性和 ACK |
| 路线格式 | 自有 JSON payload + GPX 导入源 | 可复用现有模型 |
| 定位记录 | 手表端定位能力 | 需要验证息屏、锁屏、断连、长时间采样 |
| 运动数据 | 华为 Health Kit / Health Service Kit 或自有会话数据 | Health 数据权限后置 |
| 提醒 | 震动、通知、状态条 | 需要验证手表端 API 和权限 |
| 地图 | 华为可用地图组件或自绘路线画布 | 不承诺复用系统离线地图 |
| 分发 | AppGallery Connect / 手表端应用市场 | 需要账号、签名、真机和审核路径验证 |

## 数据与协议

WATCH 系列优先复用现有核心模型：

| 对象 | 复用策略 |
| --- | --- |
| `HikingRoute` | 路线摘要、版本、校验和来源字段复用 |
| `RouteVariant.simplifiedForWatch` | 改名含义可扩展为 `simplifiedForWearable`，用于 WATCH 绘制和偏航 |
| `Waypoint` / `TurnPoint` | 用于关键点和转向提醒 |
| `HikingSession` | WATCH 创建会话，结束后回传手机 |
| `TrackPoint` | WATCH 采集实际轨迹 |
| `SessionEvent` | 记录偏航、暂停、恢复、结束、定位不稳、电量提醒 |
| `SyncEnvelope` | 可抽象为平台无关同步封包，底层由 Wear Engine 承载 |

首轮不要为了华为单独发明一套路线语义。平台差异应落在传输、权限、渲染和后台策略上。

## 第一版暂不做

1. 支持所有华为手表。
2. 支持 WATCH GT / FIT / Ultimate / D 系列的完整同等体验。
3. iPhone 与华为 WATCH 的深度联动主路径。
4. WATCH 端路线社区、附近路线发现或 AI 推荐。
5. WATCH 端复杂 GPX 编辑。
6. 完整离线地图和多地图源。
7. eSIM 独立下载路线、独立账号登录和脱离手机全量云同步。
8. 写入华为健康运动记录作为 P0。
9. AppGallery 正式上架承诺。

## 验证通过标准

| 阶段 | 标准 |
| --- | --- |
| H-WATCH-0 环境 | DevEco Studio 可创建并运行 WATCH Wearable Demo |
| H-WATCH-1 安装 | WATCH 5 / 4 真机可安装并打开手表端 App |
| H-WATCH-2 路线同步 | 手机下发路线 payload，WATCH 保存并回 ACK |
| H-WATCH-3 会话 | WATCH 可开始、暂停、继续、结束一次路线会话 |
| H-WATCH-4 定位 | 户外 30-60 分钟记录不中断，轨迹点可回传 |
| H-WATCH-5 偏航 | 偏航状态机可运行，震动提醒可感知 |
| H-WATCH-6 复盘 | 手机收到轨迹、摘要和事件，并能展示复盘 |

## 与 WatchOS MVP 的关系

| 项 | WatchOS MVP | 华为 WATCH 系列 MVP |
| --- | --- | --- |
| 首发状态 | 当前主线 | Apple Watch MVP 之后验证 |
| 手表角色 | 主导航端 | 主导航端，待验证 |
| 手机角色 | iPhone 准备和复盘 | 华为 / Android 手机准备和复盘 |
| 同步 | WatchConnectivity | Wear Engine 或已验证链路 |
| 地图 | MapKit 标准底图 | 华为地图组件或自绘兜底，需验证 |
| 运动数据 | HealthKit / HKWorkoutSession | 自有会话优先，Health Kit 后置 |
| 风险等级 | 已进入工程 MVP | 平台能力、真机、分发路径均需验证 |

## 后续定义顺序

1. WATCH 路线 payload 与 ACK 字段。
2. WATCH 地图页 / 自绘路线页线框。
3. WATCH 定位、后台和电量测试 checklist。
4. Wear Engine 真机通信测试流程。
5. WATCH 会话回传与手机复盘适配。
6. AppGallery Connect 内测和上架材料清单。
