# iPhone 路线详情与复盘页面规格 v0.1

更新日期：2026-06-05

## 目标

iPhone 端负责徒步前准备和徒步后复盘。

它不抢 Watch 行进中的主导航体验，而是帮助用户完成两个判断：

1. 出发前：这条路线是否可走、是否已同步到 Watch、是否准备好了。
2. 结束后：实际走了哪里、有没有偏航、轨迹是否完整保存。

## 页面总览

| 页面 | 阶段 | 核心目标 |
| --- | --- | --- |
| 路线列表 | 出发前 | 从远端接口获取路线列表，或找到本地/导入路线 |
| 路线详情 | 出发前 | 确认路线并同步到 Watch |
| 同步状态 | 出发前 | 判断 Watch 是否就绪 |
| 进行中状态 | 行进中 | 查看 Watch 最近状态，不作为主导航 |
| 复盘详情 | 结束后 | 查看计划路线和实际轨迹 |
| 历史记录 | 结束后 | 管理已完成会话 |

MVP 重点做远端路线列表、路线详情和复盘详情。

## 路线列表页

### 用户目标

用户在 iPhone 上看到服务端提供的可用路线，并能选择一条路线进入详情页。

远端路线列表是“官方/运营维护的路线目录”，不是路线社区、附近路线发现或 AI 推荐。

### 列表来源

| 来源 | MVP | 说明 |
| --- | --- | --- |
| 远端路线接口 | 是 | iPhone 拉取路线摘要列表 |
| 本地已保存路线 | 是 | 已下载、已导入或已同步过的路线 |
| GPX 导入 | 是 | 用户从文件导入路线 |
| 路线社区 | 否 | 不做用户发布、评论、点赞 |
| AI 推荐路线 | 否 | 不做自动推荐和个性化排序 |

### 远端列表内容

远端接口列表项至少显示：

1. 路线名称。
2. 路线距离。
3. 累计爬升。
4. 预计耗时。
5. 起点和终点或区域名称。
6. 路线质量或官方状态。
7. 本地状态：未下载 / 已下载 / 有更新 / 已同步到 Watch。

### 列表交互

1. 默认进入“远端路线”列表。
2. 支持下拉刷新远端列表。
3. 支持按名称、编号或区域搜索远端路线。
4. 点击远端路线后，进入路线详情页；如果本地没有完整路线点，先下载详情和路线 payload。
5. 下载失败时保留列表摘要，并显示可重试状态。
6. 本地已保存路线可以离线进入详情；远端刷新失败不影响本地路线。

### 远端路线详情下载

远端列表接口只返回摘要，不应把完整 GPX 点序列塞进列表响应。

详情页需要完整路线时再获取：

1. 路线详情摘要。
2. 原始路线或服务端标准路线点。
3. Watch 可用简化路线，或由 iPhone 本地生成的简化路线。
4. 起终点、关键点和转向点。
5. `remoteRouteId`、`remoteVersion`、`checksum`。

下载并校验成功后，写入本地 `HikingRoute`，再进入同步到 Watch 流程。

## 路线详情页

### 用户目标

用户在出发前确认路线，并把路线同步到 Watch。

### 页面结构

```txt
┌──────────────────────┐
│ 地图：计划路线全览     │
│ 起点/终点/关键点       │
├──────────────────────┤
│ 路线名称               │
│ 距离  爬升  预计耗时    │
│ 起点  终点             │
├──────────────────────┤
│ Watch 就绪状态         │
│ 电量 / 连接 / 权限      │
├──────────────────────┤
│ 同步到 Watch / 开始准备 │
└──────────────────────┘
```

### 地图内容

| 元素 | 必须 | 说明 |
| --- | --- | --- |
| Apple 地图底图 | 是 | 使用 MapKit |
| 计划路线 | 是 | 主视觉 |
| 起点 | 是 | 明确路线开始 |
| 终点 | 是 | 明确路线结束 |
| 转向点 | 否 | MVP 可显示数量，不必全部标出 |
| 关键点 | 否 | 有 GPX waypoint 时显示 |
| 当前位置 | 是 | 判断离起点距离 |

如果使用国内 GCJ02 地图瓦片，地图内容中的计划路线、起终点、当前位置和后续复盘轨迹必须在显示层从 WGS84 转为 GCJ02 后再叠加；路线详情、同步载荷、会话轨迹和导出数据仍保存 WGS84。

### 路线摘要

必须显示：

1. 路线名称。
2. 路线距离。
3. 累计爬升。
4. 预计耗时。
5. 起点和终点。
6. 路线点数量或路线质量提示。
7. 转向点数量。

### Watch 准备状态

路线详情页要给用户一个明确结论：Watch 是否可以出发。

| 检查项 | 显示 | 阻断同步/开始 |
| --- | --- | --- |
| Watch 连接 | 已连接 / 未连接 | 不阻断排队同步 |
| Watch 电量 | 电量百分比 | 不阻断，低电量提示 |
| 路线同步 | 未同步 / 同步中 / 已就绪 / 失败 | 未就绪时不能在 Watch 开始该路线 |
| 定位权限 | 已授权 / 未授权 | 未授权阻断 Watch 开始 |
| HealthKit 权限 | 已授权 / 未授权 | 不阻断，提示数据不完整 |
| 路线质量 | 正常 / 点太少 / 点太稀 | 不阻断，提示偏航可能不准 |

### 主操作

| 状态 | 主按钮 |
| --- | --- |
| 未同步 | 同步到 Watch |
| 同步中 | 正在同步 |
| 已同步 | Watch 已就绪 |
| 同步失败 | 重试同步 |
| Watch 不在线 | 等待 Watch 连接 |

MVP 不需要 iPhone 上直接开始 Watch 徒步。开始动作放在 Watch，避免用户以为手机是行进主控。

## 导入后的路线质量提示

GPX 导入后，iPhone 应检查路线是否适合 Watch 跟随。

| 问题 | 判断方式 | 提示 |
| --- | --- | --- |
| 点数过少 | 点数量低于阈值 | 路线点较少，偏航提醒可能不准 |
| 点间距过大 | 相邻点距离超过阈值 | 路线较粗略，山路弯道可能不准确 |
| 无海拔 | GPX 无 elevation | 爬升数据可能缺失 |
| 路线太长 | 距离或点数过大 | 已为 Watch 生成简化路线 |
| 起点较远 | 当前距离起点过远 | 你离起点还有 Xm |

这些提示不应吓人，但要诚实。户外产品的信任感来自这种诚实。

## 进行中状态页

### 目标

iPhone 行进中只做辅助状态，不做主导航。

显示：

1. 当前路线名称。
2. Watch 会话状态。
3. 最近同步时间。
4. Watch 电量。
5. 当前距离和用时。
6. 当前是否偏航。

不做：

1. 大地图实时导航主视图。
2. 复杂控制 Watch 会话。
3. 高频轨迹动画。

原因：

产品核心是少掏手机。iPhone 只需要让用户确认 Watch 还在记录。

## 复盘详情页

### 用户目标

用户结束徒步后，确认轨迹已保存，并看懂实际走法和偏航位置。

### 页面结构

```txt
┌──────────────────────┐
│ 地图：计划路线 + 实际轨迹 │
│ 偏航点 / 起点 / 终点      │
├──────────────────────┤
│ 距离  用时  爬升          │
│ 移动时间  平均速度        │
├──────────────────────┤
│ 偏航事件 / 暂停区间        │
├──────────────────────┤
│ 导出 GPX / 分享           │
└──────────────────────┘
```

### 地图叠加

| 元素 | 必须 | 视觉建议 |
| --- | --- | --- |
| 计划路线 | 是 | 明亮主线 |
| 实际轨迹 | 是 | 另一种颜色或半透明线 |
| 偏航段 | 是 | 警示色高亮 |
| 起点/终点 | 是 | 简洁标记 |
| 暂停点 | 否 | MVP 可不显示 |
| 转向提醒点 | 否 | 后续用于诊断提醒质量 |
| 当前位置 | 否 | 结束后不需要 |

### 摘要数据

必须显示：

1. 实际距离。
2. 总用时。
3. 移动时间。
4. 累计爬升。
5. 平均速度。
6. 最高/最低海拔。
7. 偏航次数。
8. 轨迹同步状态。

可选显示：

1. 平均心率。
2. 最大心率。
3. 能量消耗。
4. 路线完成度。

### 偏航复盘

偏航事件列表显示：

| 内容 | 说明 |
| --- | --- |
| 发生时间 | 例如开始后 42 分钟 |
| 持续时间 | 偏航到回到路线的时间 |
| 最大偏航距离 | 例如 102m |
| 地图定位 | 点击后地图聚焦偏航段 |

MVP 不需要评价用户“走得好不好”，只需要客观展示哪里偏离过。

## 同步状态处理

复盘页要清楚表达轨迹是否完整。

| 状态 | 页面表现 | 用户动作 |
| --- | --- | --- |
| 同步中 | 显示正在接收 Watch 数据 | 等待 |
| 部分同步 | 地图显示已收到轨迹，提示未完整 | 等待 Watch 连接 |
| 已完成 | 显示完整复盘 | 可导出 |
| 同步失败 | 显示失败原因 | 重试或等待 Watch |
| 路线缺失 | 可显示实际轨迹，提示计划路线缺失 | 从 Watch 或本地补路线 |

原则：

1. 即使只有部分轨迹，也要显示已收到部分。
2. 不要因为计划路线缺失而隐藏实际轨迹。
3. 导出前要提示数据是否完整。

## 历史记录

MVP 历史列表显示：

1. 路线名称。
2. 日期。
3. 距离。
4. 用时。
5. 偏航次数。
6. 同步状态。

历史记录筛选和搜索可以后置；远端路线列表的名称、编号或区域搜索仍属于 MVP。

## 导出与分享

MVP 支持 GPX 导出即可。

导出内容：

1. 实际轨迹。
2. 起点和终点。
3. 可选偏航事件作为 waypoint。

后续再考虑：

1. FIT。
2. TCX。
3. 图片分享。
4. 路线对比报告。

## 空状态和异常状态

| 状态 | 页面 | 处理 |
| --- | --- | --- |
| 无路线 | 路线列表 | 引导刷新远端路线或导入 GPX |
| 远端列表刷新失败 | 路线列表 | 显示失败原因，保留本地已保存路线 |
| 远端路线详情下载失败 | 路线详情 | 保留摘要，可重试下载 |
| 远端路线有更新 | 路线列表 / 路线详情 | 标记有更新，用户确认后更新本地路线版本 |
| 导入失败 | 导入页 | 显示失败原因 |
| Watch 不在线 | 路线详情 | 允许排队同步 |
| 同步失败 | 路线详情 | 可重试，保留旧路线 |
| 会话未完整同步 | 复盘页 | 显示部分轨迹，等待补传 |
| HealthKit 数据缺失 | 复盘页 | 地图和轨迹正常，健康数据为空 |
| 计划路线缺失 | 复盘页 | 显示实际轨迹，提示无法做路线对比 |

## MVP 验收标准

1. iPhone 能从远端接口获取路线列表并展示摘要。
2. iPhone 能下载远端路线详情，校验后保存为本地路线。
3. iPhone 能导入 GPX 并展示路线详情。
4. 路线详情页能显示地图、距离、爬升、预计耗时和起终点。
5. 路线详情页能显示 Watch 同步状态。
6. 用户能从路线详情页同步路线到 Watch。
7. 结束后 iPhone 能显示计划路线和实际轨迹叠加。
8. 复盘页能显示偏航事件。
9. 复盘页能表达轨迹同步是否完整。
10. 没有 HealthKit 数据时，复盘页仍可展示轨迹。
11. 实际轨迹可以导出为 GPX。

## 待设计问题

1. 路线详情页地图和摘要的首屏比例。
2. Watch 就绪状态是否用 checklist 还是单一状态条。
3. 偏航段在地图上的高亮样式。
4. 复盘页是否需要海拔曲线作为 MVP。
5. 路线质量提示的文案强度。
6. 远端路线列表是否需要地区筛选作为 MVP。
7. 远端详情接口返回原始路线点，还是直接返回 Watch 简化路线 payload。
