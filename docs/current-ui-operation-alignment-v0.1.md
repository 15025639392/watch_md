# 当前 UI 与操作逻辑对齐说明 v0.1

更新日期：2026-06-06

## 文档目标

本文用于约束后续 AI 和开发者理解当前工程中的 UI、操作入口和数据语义。它不是新的产品扩展，而是把当前已落代码、HTML 原型和目标规格之间容易混淆的地方说清楚。

阅读规则：

1. “当前实现”表示 `watch-hiking-app/` 中已经落代码的行为。
2. “目标规格”表示核心规格文档要求但当前代码可能尚未完全实现的行为。
3. “临时实现”不能自动升级为产品规则；除非本文或核心规格明确说明，否则后续开发应逐步向目标规格收敛。
4. 如果代码、原型和规格冲突，优先按本文的语义边界判断，再同步修正文档或代码。

## 当前工程范围

当前 `watch-hiking-app/` 已经不是纯文档仓库的一部分，而是 Apple Watch 徒步 MVP 的工程骨架。

已落代码的主流程：

```txt
iPhone 路线列表 / GPX 导入
  -> iPhone 路线详情
  -> WatchConnectivity 路线下发
  -> Watch 地图优先首页
  -> Watch 开始 / 暂停 / 继续 / 结束
  -> Watch 会话上传
  -> iPhone Watch 中枢接收
  -> iPhone 回传详情 / 实际轨迹复盘
```

仍需真机或后续 slice 验证的内容不能写成已实测事实，包括 WatchConnectivity 断连/后台/锁屏/重连表现、Core Location 长时间采样、HKWorkoutSession 长时间生命周期、Watch 地图性能、偏航误报率和电量策略。

## iPhone 当前 UI

### 路线列表

当前 iPhone 首屏是“路线”列表，不是营销页或设置页。

页面结构：

1. 顶部是 Watch 中枢状态卡，展示连接状态、已接收 Watch 会话数和待处理回传数。
2. 状态卡可点击进入“Watch 中枢”。
3. 下方是 iPhone 定位状态卡，展示真实定位的坐标、精度、朝向和更新时间。
4. 定位卡请求 iPhone When In Use 定位并显示 Core Location 位置 / heading；打开“持续高精度定位”后请求 Always 授权，并启用 iOS `location` 后台模式以便 App 退到后台后继续接收位置更新。
5. 再下方是三段筛选：`远端路线`、`本地`、`已同步`。
6. 顶部工具栏提供“导入 GPX”。
7. 搜索框提示为“名称、编号或区域”。

列表语义：

| Tab | 当前内容 | 说明 |
| --- | --- | --- |
| 远端路线 | `MockRemoteRouteClient` 返回的路线摘要 | 当前是 mock 目录，不代表真实服务端已接入 |
| 本地 | 已导入或已下载并保存的路线 | 包含 GPX 导入结果 |
| 已同步 | 本次运行中收到 Watch 安装 ACK 的路线 | 当前仍需真机验证断连、后台、锁屏和重连表现 |

空状态显示“暂无路线”，引导刷新远端目录或导入 GPX。

### 路线详情

路线详情是全屏地图预览加底部信息面板。

当前 UI：

1. 地图全屏显示计划路线、起点和终点。
2. 左上角关闭按钮返回列表。
3. 右上角提供 iPhone 地图图层切换：`标准`、`卫星`、`混合`。
4. 如果 iPhone 定位卡已经产生当前位置，地图上会显示接近 iOS 地图蓝点风格的定位标记：半透明精度圈、蓝色圆点和方向楔形，并随定位点和朝向更新。
5. 底部面板展示同步状态、路线名称、距离、爬升、预计用时、起终点识别、路线点数和转向点数。
6. “Watch 出发检查”显示路线同步、连接状态、定位 / 健康权限三项。
7. 主按钮根据状态显示“同步到 Watch”“重新同步到 Watch”或“重试同步”。

语义边界：

1. iPhone 路线详情不提供“开始徒步”。
2. iPhone 图层切换入口只适用于 iPhone 路线预览；Watch 地图页仍按 watchOS MVP 规格固定使用标准底图，不提供图层切换入口。
3. 当前同步使用 `iPhoneSessionSyncService` 通过 WatchConnectivity 发送 `routeManifest` / `routePayload`，两端 reachable 时优先走 `sendMessageData`，不可达或实时发送失败时回退到 `transferUserInfo` 可靠队列，并等待 Watch 返回 ACK。
4. “Watch 已就绪”在当前实现中表示已收到 Watch 安装 ACK；已用 iPhone 模拟器 + 配套 Watch 模拟器验证 manifest / payload / ACK / Watch 落盘闭环，但断连、后台、锁屏、重连和大路线 payload 表现仍需真机验证。
5. iPhone 首屏定位卡只是当前定位状态展示和调试入口，不写入徒步会话轨迹，也不替代 Watch 端开始 / 暂停 / 继续 / 结束流程。
6. iPhone 后台持续定位依赖用户授予“始终允许”定位权限和系统后台调度；退后台长时间稳定性、耗电和系统提示表现仍需真机验证。

### Watch 中枢

Watch 中枢用于查看 Watch 会话回传，不是路线管理页。

当前 UI：

1. 顶部是“实时轨迹”地图卡，地图为主体；iOS Watch 中枢实时地图参考路线详情的混合图层，使用 Apple MapKit 混合图层（卫星底图 + 路网标注），WatchConnectivity 同步可用性、最近同步消息、待处理数量、Watch 当前位置、健康指标和偏航状态以半透明浮层显示在地图上。
2. Watch 开始徒步后，iPhone 可看到 Watch 最近轨迹、当前位置、顶部状态、底部提示、心率、距离、能量、待处理回传数和明确的 Watch 回传时间。
3. iPhone Watch 中枢实时卡的“顶部状态 / 底部提示 / 心率 / 距离 / 能量”应尽量和 Watch 底部浮层保持同一套语义；确认偏航时显示向哪个方向回到路线、距离路线多远，并可附带最近路线投影点坐标；当 iPhone 未拿到路线总距离或回路线方向时，可以降级显示路线进度或“回到路线”。
4. 没有会话时显示“Watch 等待徒步记录”。
5. 有会话时按“待处理”和“已完成”分组。
6. 点击会话进入“回传详情”。

同步语义：

1. Watch -> iPhone 会话回传已用 iPhone 模拟器 + 配套 Watch 模拟器验证 status / track chunk / event chunk / summary / ACK 流程。
2. iPhone 收齐摘要、最终轨迹和最终事件后会把会话保存到 `ReceivedSessions`，外层记录和摘要内的 `syncStatus` 都应显示为 `synced`。
3. iPhone UI 中“Watch 已连接”只表示 `isReachable == true` 时可实时通信；Watch 退到后台或未实时可达时，当前实现显示“Watch 后台同步可用”，并通过 `transferUserInfo` 可靠队列同步，不能误写成路线或会话无法同步。
4. Watch 行进中会发送 `liveTrackSnapshot` 轻量快照，包含当前位置、最近轨迹点、HealthKit 实时指标、路线匹配 / 偏航状态、回路线方位角和最近路线投影点，用于 iPhone Watch 中枢实时预览；它不替代结束后的 `trackChunk` / `eventChunk` / `sessionSummary` 完整归档回传。
5. `liveTrackSnapshot` 在 Watch 后台或非实时可达时允许进入 `transferUserInfo` 队列，更新频率受系统调度影响，不能承诺严格实时。
6. 断连、后台、锁屏、重连和大体量 chunk 的真实设备表现仍需 iPhone + Apple Watch 真机验证。

回传详情显示：

1. 同步状态。
2. 轨迹点、事件、缺口、距离、时长和偏航数量。
3. 轨迹、事件、摘要、状态的完整性。
4. 缺失 sequence 范围。
5. 同步完成后显示“查看复盘”。

### iPhone 复盘

当前复盘页只稳定表达“实际轨迹复盘”。

当前 UI：

1. 地图显示 Watch 回传的实际轨迹。
2. 起点和终点来自实际轨迹的第一个和最后一个点。
3. 底部摘要面板显示同步完成状态、日期、会话标题和同步指标。

目标规格中“计划路线与实际轨迹叠加、偏航段高亮、偏航事件列表、GPX 导出”仍是后续实现项。后续 AI 不应因为目标规格存在就假设当前复盘代码已经具备这些能力。

## Watch 当前 UI

### 首屏

当前 Watch App 首屏是地图优先页面。

加载规则：

1. App 启动后先创建内部“自由记录”占位路线。
2. 如果本地 `WatchInstalledRoutes` 中存在已安装路线，再切换为本地安装路线。
3. 如果恢复到未结束会话，读取本地会话快照、轨迹点和最后位置。

重要语义：

1. “自由记录”占位路线是当前实现为复用会话模型而创建的内部对象。
2. 该占位路线不能在产品语义上当作真实计划路线。
3. 自由记录模式不显示计划路线、起点、终点、剩余距离、偏航状态或转向提醒。
4. 当前代码中 `canStart` 依赖 `route != nil`；因为自由记录占位路线总会被创建，所以无真实路线时也能开始记录。

### 地图显示

当前 Watch 地图使用 Apple MapKit 标准底图。

有真实计划路线时：

1. 计划路线用 cyan 线显示。
2. 已走轨迹用 orange 半透明线显示。
3. 当前点用 `location.north.fill` 蓝色圆形标记显示。
4. 起点为绿色小圆点，终点为红色小圆点。
5. 确认偏航时显示当前位置到最近路线投影点的红色虚线。

自由记录时：

1. 不显示计划路线。
2. 不显示起点和终点。
3. 只显示当前点和已走轨迹。
4. 不执行路线匹配、偏航或剩余距离计算。

地图交互：

1. 点击地图切换底部浮层显示 / 隐藏。
2. 当前代码没有独立数据页、完整控制页或长按菜单。
3. Digital Crown 缩放属于目标规格，当前代码没有显式实现专用缩放控制。

### 底部浮层

当前 Watch 的状态、指标和操作都集中在底部浮层。

浮层内容：

1. 第一行是状态提示：状态色条、状态文案、可选回路线方向箭头、底部提示文案。
2. 第二行是三个紧凑指标：心率、距离、能量。
3. 第三行是紧凑操作按钮。

状态文案优先级：

| 场景 | 顶部状态 | 底部提示 |
| --- | --- | --- |
| 已结束 | 已结束 | 路线距离或当前状态 |
| 暂停 | 已暂停 | 记录暂停中 |
| 自由记录未开始 | 自由记录 | 无路线也可开始 |
| 自由记录中 | 自由记录中 | 记录实际轨迹 |
| 路线上 | 路线上 | 剩余距离 |
| 疑似偏航 | 路线待确认 | 剩余距离或路线距离 |
| 确认偏航 | 偏离 Xm | 向某方向回到路线 |
| 定位不稳 | 定位不稳 | 剩余距离或路线距离 |
| 已加载路线但未开始 | 路线名称 | 路线距离 |

指标语义：

1. 心率、能量和运动距离来自 `HKLiveWorkoutBuilder` 的实时指标。
2. 指标为空时显示 `-- bpm`、`-- kcal` 或 `--`。
3. 这些指标当前不等同于最终 `SessionSummary` 已完整写入。

### Watch 操作按钮

当前操作是紧凑按钮，不是独立控制页。

按钮状态：

| 会话状态 | 显示按钮 |
| --- | --- |
| 未开始 | 开始 |
| active | 暂停、结束 |
| paused | 继续、结束 |
| 结束确认中 | 取消、确认结束 |
| 已结束 | 不显示开始 / 暂停 / 继续 / 结束 |

结束确认：

1. 当前实现是在底部按钮区把“结束”替换成“取消”和“确认结束”。
2. 这满足二次确认的最低要求。
3. 目标规格中的完整结束确认页、距离 / 用时 / 保存轨迹说明仍可后续补齐。

暂停 / 继续：

1. 暂停时停止定位采样、暂停 workout，并写入 pause 事件。
2. 暂停期间不写正式轨迹点。
3. 继续时恢复会话、workout 和定位采样。

持续定位当前配置：

1. Watch target 已配置 `UIBackgroundModes = location` 和 `WKBackgroundModes = workout-processing`。
2. `WatchLocationSampler` 启动后设置 `allowsBackgroundLocationUpdates = true`。
3. 该配置用于支持徒步中息屏或 App 退到后台后的持续定位；长时间稳定性、耗电和系统调度表现仍需 Apple Watch 真机验证。

结束：

1. 结束时停止定位和 workout。
2. 如果会话处于 paused，先恢复再结束，以便 recorder 完成状态机。
3. 生成 `SessionSummary`。
4. 读取本地会话快照并触发上传计划。
5. 会话结束后 `session` 置空，地图保留摘要和轨迹状态。

## 偏航与定位当前语义

当前偏航 MVP 使用计划路线线段投影，不依赖地图底图。

阈值：

| 参数 | 当前代码值 |
| --- | --- |
| 偏航阈值 | 30m |
| 回归阈值 | 20m |
| 定位弱阈值 | 50m |
| 确认偏航连续点数 | 3 |
| 持续偏航事件限频 | 120s |

状态机：

1. 定位精度差于 50m 时进入 `locationUnreliable`，不触发偏航。
2. 超过 30m 但不足连续 3 个可信点时为疑似偏航，UI 显示“路线待确认”。
3. 连续 3 个可信点超过 30m 后为确认偏航，UI 显示“偏离 Xm”并触发 failure 触觉。
4. 回到 20m 内后写入 `offRouteEnded` 并触发 success 触觉。
5. 持续偏航每 120s 写入一次 `offRouteUpdated`。

自由记录模式下 `matcher == nil`，不会产生 `nearestRouteDistanceMeters`、`routeProgressMeters`、偏航事件或定位恢复事件。

## 目标规格但当前未完全实现

以下能力是目标规格或 HTML 原型里的方向，不能被后续 AI 误判为当前已完成：

1. Watch 真实路线下发到手表本地路线库。
2. Watch 多条已安装路线选择页。
3. Watch 独立路线就绪卡片和“使用此路线开始”确认层。
4. 自由记录中途收到路线后的接入判断与用户确认层。
5. Watch 接近转向点提醒和下一段路线高亮。
6. Watch 接近终点提醒。
7. Watch 完整控制页、数据页、安全页和长按菜单。
8. Watch 低电量模式 UI 与采样策略切换。
9. iPhone 行进中低频状态页。
10. iPhone 复盘中的计划路线叠加、偏航段高亮、偏航事件列表和 GPX 导出。
11. 真实服务端路线搜索 / 详情接口。
12. 真机配对安装、签名、断连、后台、锁屏和重连验证闭环。

## 后续修改原则

1. 如果修改当前 SwiftUI 页面结构，先同步本文对应章节，再检查 `ios-watchos-operation-data-linkage-v0.1.md`、`watchos-map-page-spec-v0.1.md` 和 `hiking-session-flow-v0.1.md`。
2. 如果把某个目标能力落代码，需要把它从“当前未完全实现”移到对应“当前实现”章节。
3. 如果删除临时实现，例如自由记录占位路线，需要同时更新数据模型中自由记录会话的识别方式。
4. 如果接入真实 WatchConnectivity 路线下发，必须明确 mock transport 与真实 transport 的 UI 状态差异。
5. 如果接入真机验证结果，注明验证日期、设备、系统版本和仍未覆盖的场景。
